# Blueprint Platform Request Jasa Digital

Tanggal: 5 Mei 2026  
Status: Draft produk -> produk -> roadmap  
Target awal: client dari Instagram/TikTok/WhatsApp bio link, prioritas UMKM/lokal, individu, startup kecil, dan mahasiswa.

## 1. Ringkasan Konsep

Platform ini bukan marketplace freelance penuh di awal. Versi pertama lebih tepat disebut:

> platform request jasa digital + negosiasi + tracking project ringan.

Client datang dari bio link sosial media, mengisi request dulu, lalu membuat akun agar bisa memantau progress, chat/thread dengan admin/worker, melihat penawaran, dan upload file pendukung. Di sisi worker/admin, kamu bisa melihat request masuk, memberi penawaran, nego, update status, dan mengelola pekerjaan.

Fokus awal:

- Cepat live.
- Mudah dipakai client dari HP.
- Admin solo dulu, tapi database siap multi-worker.
- Pembayaran manual dulu, tapi struktur data sudah siap untuk payment gateway.
- Working brand: **Nama Nanti, Digital Dulu**.
- Brand terasa santai, profesional, approachable, cocok untuk UMKM dan mahasiswa.

## 2. Working Brand

Nama sementara: **Nama Nanti, Digital Dulu**.

Nama ini dipakai sebagai placeholder strategis: brand final belum perlu dikunci sekarang, tapi arah produk, konten, dan sistem tetap bisa jalan. Secara tone, nama ini terasa santai, jujur, dan cocok untuk fase awal karena tidak memaksakan identitas yang belum matang.

Tagline kerja:

> Nama nanti, digital dulu. Request kerja digital kamu, biar kami bantu beresin.

### Cara pakai sementara

- Website bisa memakai **Nama Nanti, Digital Dulu** sebagai nama campaign/brand sementara.
- Instagram bisa memakai handle sementara yang masih fleksibel, misalnya `@namanantidigitaldulu` jika tersedia, atau variasi pendeknya.
- Setelah sudah ada beberapa request, testimoni, dan arah layanan yang paling laku, nama final bisa dipilih dengan data yang lebih nyata.

### Kenapa tidak mengunci nama terlalu cepat?

- Produk masih mencari layanan paling kuat: web, office, automation, app kecil, atau kombinasi.
- Nama final perlu dicek domain, username sosial media, dan merek.
- Untuk awal, positioning dan flow lebih penting daripada nama permanen.

## 5. Flow Client

### Flow utama dari bio link

1. Client klik link bio Instagram/TikTok.
2. Masuk ke landing page ringkas.
3. Klik "Kirim Request".
4. Isi form request:
   - Nama
   - Email
   - Nomor WhatsApp
   - Kategori
   - Detail kategori/contoh kebutuhan
   - Judul request
   - Deskripsi
   - Range budget
   - Nominal budget awal
   - Deadline harapan
   - Upload file opsional
5. Setelah submit, client diminta membuat akun atau login.
6. Request tersimpan dan terhubung ke akun client.
7. Client masuk dashboard untuk melihat:
   - status request
   - penawaran admin
   - thread pesan
   - file upload
   - riwayat status

### Kenapa form dulu baru akun?

Untuk traffic dari sosial media, form dulu lebih ringan. Orang bisa cerita kebutuhan dulu sebelum merasa "dipaksa daftar".

## 6. Flow Admin/Worker

1. Admin login.
2. Admin melihat daftar request baru.
3. Admin membuka detail request.
4. Admin bisa:
   - update status
   - kirim pesan
   - membuat penawaran
   - upload file
   - menambah catatan internal
   - assign worker
5. Client menerima penawaran di dashboard.
6. Client bisa:
   - accept
   - reject
   - nego lewat thread
7. Setelah deal:
   - status menjadi `approved` atau `working`
   - payment manual dicatat sebagai status/record pembayaran
8. Setelah pekerjaan selesai:
   - admin upload hasil
   - status `review`
   - jika sudah oke, status `waiting_final_payment` atau `done`

## 7. Status Request

Status MVP yang disarankan:

- `submitted`: request baru masuk.
- `reviewing`: admin sedang cek kebutuhan.
- `negotiating`: sedang nego harga/scope/timeline.
- `waiting_approval`: admin sudah kasih penawaran, menunggu client setuju.
- `approved`: penawaran disetujui.
- `waiting_payment`: menunggu DP/pembayaran manual.
- `working`: sedang dikerjakan.
- `waiting_client`: menunggu feedback/data/file dari client.
- `revision`: sedang revisi.
- `waiting_final_payment`: menunggu pelunasan.
- `done`: selesai.
- `cancelled`: dibatalkan.

Untuk UI, jangan tampilkan kode teknis. Tampilkan label Indonesia:

- Baru masuk
- Dicek dulu
- Nego
- Menunggu persetujuan
- Disetujui
- Menunggu pembayaran
- Dikerjakan
- Menunggu client
- Revisi
- Menunggu pelunasan
- Selesai
- Dibatalkan

## 13. Supabase Step-by-Step

### A. Buat project

1. Buka [supabase.com](https://supabase.com/).
2. Sign up/login.
3. Create new project.
4. Pilih organization.
5. Isi:
   - Project name: nama brand kamu.
   - Database password: simpan aman.
   - Region: pilih Singapore kalau tersedia.
6. Tunggu project selesai dibuat.

### B. Ambil env keys

1. Masuk Project Settings.
2. Buka API.
3. Simpan:
   - Project URL
   - anon public key
   - service role key, hanya untuk server/admin, jangan expose ke browser.

Untuk Next.js:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

### C. Aktifkan Auth email

1. Buka Authentication.
2. Providers.
3. Pastikan Email aktif.
4. Untuk MVP, bisa aktifkan confirm email atau matikan dulu saat development.

Saran:

- Development: boleh matikan email confirmation agar cepat test.
- Production: aktifkan email confirmation.

### D. Aktifkan Google login

1. Buka Google Cloud Console.
2. Create project.
3. Configure OAuth consent screen.
4. Create OAuth Client ID.
5. Authorized redirect URL dari Supabase:
   - Supabase Authentication -> Providers -> Google.
   - Copy callback URL.
6. Masukkan Client ID dan Client Secret ke Supabase Google provider.
7. Enable Google provider.

### E. Setup Storage

Bucket:

- `request-files`: private.
- `deliverables`: private.

Semua file harus private. Client hanya boleh akses file yang terkait request miliknya. Admin/worker boleh akses request yang ditangani.

create or replace function public.is_staff(user_id uuid)
returns boolean
language sql
stable
security definer
as $$
  select exists (
    select 1
    from public.profiles
    where id = user_id
      and role in ('worker', 'admin')
  );
$$;

create policy "categories readable by everyone"
on public.service_categories
for select
using (is_active = true);

create policy "profiles can read own profile"
on public.profiles
for select
using (auth.uid() = id or public.is_staff(auth.uid()));

create policy "profiles can update own profile"
on public.profiles
for update
using (auth.uid() = id)
with check (auth.uid() = id);

create policy "clients can read own requests and staff can read all"
on public.requests
for select
using (client_id = auth.uid() or public.is_staff(auth.uid()));

create policy "clients can create own requests"
on public.requests
for insert
with check (client_id = auth.uid() or public.is_staff(auth.uid()));

create policy "staff can update requests"
on public.requests
for update
using (public.is_staff(auth.uid()))
with check (public.is_staff(auth.uid()));

create policy "request files visible to owner and staff"
on public.request_files
for select
using (
  public.is_staff(auth.uid())
  or exists (
    select 1 from public.requests r
    where r.id = request_files.request_id
      and r.client_id = auth.uid()
  )
);

## 15. Catatan Implementasi Auth Profile

Saat user daftar, perlu otomatis membuat row di `profiles`.

Opsi:

1. Trigger database `handle_new_user`.
2. Server action setelah signup.

Untuk MVP, trigger lebih rapi agar semua provider auth tetap membuat profile.

Contoh trigger:

```sql
create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer
as $$
begin
  insert into public.profiles (id, email, full_name)
  values (
    new.id,
    new.email,
    coalesce(new.raw_user_meta_data->>'full_name', new.raw_user_meta_data->>'name')
  );
  return new;
end;
$$;

create trigger on_auth_user_created
after insert on auth.users
for each row execute function public.handle_new_user();
```
